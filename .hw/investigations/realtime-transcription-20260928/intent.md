# リアルタイム文字起こし改善の合意

出典: この Codex タスクの会話。合意日: 2026-09-28 JST。

## 原要求

> リアルタイム文字起こしの精度をあげたい。今は致命的にダメダメ

## 提示した目的・判断軸・制約

利用者が得たい結果は、日本語会議で発言の欠落・誤変換・重複を減らし、読める字幕にすること。
直前の回答では次のように確認した。

> 表示の速さより内容の正確さを優先し、追加費用や本番変更は別途判断する方針で進めていい？

## 実際の返答と追加指示

> それでいいんだけど、比較検証の前に実装方法としてベストプラクティスをブラウジングで調べてほしい

正確さ優先と、追加費用・本番変更を別途判断する方針への合意として扱う。
次に行う作業は公式資料・研究のブラウジングによる実装方法の調査。
特定の有料 API、GPU 調達、稼働環境変更、数値目標への合意は含まない。

調査結果・実装提案・未検証事項は research.md に分離する。

## 実装への追加合意（2026-09-28、このタスク）

ユーザー原文:

> **Whisper経路を維持して改善すること。**
>
> 1. 日本語短文の削除と未処理音声の破棄を直す。
> 2. 日本語に合う確定処理、発話前後の音声保持を整える。
> 3. 現在の `tiny` からのモデル改善と、その処理を支える実行環境を検証する。
>
> これを進めよう

Whisper の HTTP API 契約を保った修正とローカル検証を進める合意。
Soniox リアルタイムへの移行は対象外。既存の追加費用・本番変更の判断条件は維持する。
モデルや実行環境の比較は検証用環境で行い、稼働中の認識サーバーや `.env` を変更しない。
実会議音声が利用できない場合、合成音声の結果を実会議精度の保証と扱わない。

3つの待ち時間を分けて追う

矢印は要求・呼び出しの方向。返り値は逆方向。橙はコードで確認した障害要因候補で、本番の原因確定や計測結果を意味しない。

AuthProvidercheckAuth → /api/auth/me認証確認まで画面を保留
MeetingsPagefetchMeetings × 2初回effectが2本
Next BFF/meetings → /bots5秒失敗で /bots/status へ。履歴が欠落

02　録音masterから再生開始

Playback hookPromise.all(master)1件失敗で全音声を消す。録音配列の参照変更でも再取得
Next BFF/master?proxy=1masterメタ情報→rawを二段取得
Gatewayresp.content全body読了まで返さない
Meeting API_build_storage_media_responseRange 200/206・8MiB窓・to_thread対応済み
Storagelocal / S3 / GCSmasterファイル。署名URL発行失敗時raw fallback

音声のmetadata解決だけでも master → download のDB検索が重複。file_exists / get_presigned_url はasync handler内で同期実行。rawの窓読みは既にthreadへ逃がしているため、両者を混同しない。

03　終了後の成果物が揃うまで

vexa-botrecording / callbacks録音断片と終了通知
Meeting APIrecordings / callbacksMeeting.data.recordingsへ保存
Finalizerrecording_finalizermasterを結合・playback_url設定
画面のpolling5s status / 2.5s artifacts未完了でも次の処理を起動。stoppingで両方稼働
PlayerAudioPlayermetadata・シーク・再試行。1500ms retryに回数上限なし

Redis stream/pubsub → collector → PostgreSQL / WebSocket → transcript-rendering で文字起こしを同期。確定文字起こしと録音masterの完成は別状態。会議がcompletedでも、録音が完成済みとは限らない。

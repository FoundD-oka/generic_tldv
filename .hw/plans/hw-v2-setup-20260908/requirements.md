# 元の依頼と制約

ユーザー原文: 「まず、新ハーネスの設定をお願いします」

直前の目的: 文字起こしの各再生ボタンは該当発言の区間だけを再生し、上部プレイヤーは通し再生を担当する。この修正の最終gateが、新ハーネス設定の未追跡により停止している。

ユーザーのAGENTS.mdにある保持条件:
- `.hw/verify-baseline` の既知失敗を保持し、新規失敗を追加して検証を通さない。
- 旧 hw の実装は `.hw/legacy/v1/` に原本を保存し、旧回帰テストからのみ使う。
- 旧 READY・固定 S/M/L・Prime の停止条件を現在の合格証明に使わない。
- 過去の plan・レビュー・学習ログと旧 harness-init の資産は保持する。
- クライアント合意済みの要求を独自に再定義しない。
- `.env` と本番デプロイ資材を書き換えない。

設定範囲:
1. 元checkoutへ適用済みのhw v2.1.3とプロジェクト固有の移行をGit管理へ移す。
2. 比較先の既定をorigin/mainに設定する。依存準備のある既存CIとプロジェクトverifyを保持する。
3. 未追跡の無関係なapp-loading-recording-refactor計画は今回のcommitへ含めない。
4. 新しいcheckoutでdoctor/verifyが動き、通常変更に対するgateの成功と、dirty tree・テスト失敗・必要なレビュー欠落時の拒否を実際に確認する。
5. GitHubの外部保護・独立App連携・初回導入のbootstrapをローカル検証成功と区別し、未設定を成功に見せない。
6. 文字起こし区間再生のブランチへ確定した設定を統合し、当該差分のv2 gateを実行可能にする。

# 社内tl;dv置き換えロードマップ

## 1. 結論

目標は、単にtl;dv相当の機能を増やすことではない。**対象となる社内会議の90%以上で、参加・録音・確定文字起こし・成果物公開までをカボスだけで安定完了し、旧ツールへの戻りを5%未満にすること**である。

最短の移行期間は約6か月を想定する。ただし日付で強制的に切り替えるのではなく、各段階のKPIを2〜4週連続で満たしたときだけ次へ進む。

「全部置き換える」の対象は、録音してよい**対象社内会議**である。人事面談、法務・懲戒、センシティブな1on1、参加者が録音を拒否した会議などは例外ポリシーを残す。例外を無理にゼロにすると、利用者が隠れて別ツールを使うため、全社定着の妨げになる。

## 2. 置き換え完了の定義

次の条件をすべて満たした状態を「社内利用の置き換え完了」とする。

1. 対象社内会議のうち90%以上で、カボスの成果物が期限内に利用可能になる。
2. カボスを試行した会議の98%以上で、参加から成果物公開までデータ欠損なく完了する。
3. 対象利用者の週次利用率が85%以上になる。
4. カボス対象会議で旧ツールを併用・代替した割合が5%未満になる。
5. 上記を4週連続で満たし、P0/P1障害、復元不能なデータ消失、重大な権限事故が0件である。
6. 旧ツールの過去データを移行するか、期限付きの閲覧専用アーカイブとして残す方針が決まっている。
7. 録音同意、閲覧権限、保持・削除、障害対応、問い合わせ窓口が運用として定着している。

## 4. KPIツリー

### 4.1 ノーススターKPI

**対象会議成功カバレッジ**

```text
期限内にカボス成果物が利用可能になった対象社内会議数
÷ 対象社内会議総数
```

成果物が利用可能とは、ボット参加、必要な録音、確定文字起こし、権限付き公開、重大欠損なし、旧ツールでのやり直しなしをすべて満たすことを指す。最終目標は週次90%以上を4週連続で達成することとする。

## 5. 段階導入ロードマップ

日付は2026年7月20日開始の仮置きである。各ゲート未達時は次段階へ進まず、2週間単位で原因を修正する。

| 段階 | 仮期間 | 対象 | 主な作業 | Exit KPI |
|---|---|---|---|---|
| Phase 0 計測・ルール | 7/20〜8/2 | 運用者・責任者 | 対象会議定義、現行tl;dv利用棚卸し、イベント計測、同意/保持/削除、障害区分、パイロット選定 | 対象会議判定率95%以上、主要KPIの母数取得、責任者承認 |
| Phase 1 管理パイロット | 8/3〜8/30 | 5〜10人、30会議以上 | tl;dvと並行運用、確定文字起こし/Drive待機・失敗解消、自動要約・決定事項・宿題の最小成果物、話者PoC | K-01 70%以上、K-04 95%以上、K-05 90%以上、K-07 80%以上、データ消失0 |
| Phase 2 1部署標準 | 8/31〜10/11 | 1部署、100会議以上 | カレンダー既定参加、オンボーディング、検索/共有導線、問い合わせ運用、運用ダッシュボード | K-01 80%以上、K-04/K-05 97%以上、K-06 90%以上、K-02 80%以上を2週連続 |
| Phase 3 全社既定 | 10/12〜12/6 | 全対象部署 | 全社既定化、権限統合、冗長実行基盤、バックアップ復旧、監視・当番、例外フロー | K-01 90%以上、K-04/K-05 98%以上、K-11 99.5%以上、K-13 0を4週連続 |
| Phase 4 旧ツール終了 | 12/7〜2027/1/31 | 全社 | 新規tl;dv録音停止、過去データ移行/閲覧専用化、ライセンス縮小、30日ロールバック窓 | K-03 5%未満、重大例外0、過去データ方針完了、費用確認 |

### Phase 0：計測・ルールを先に作る

1. 過去8週間のカレンダーとtl;dv利用を棚卸しし、会議種別・部署・利用機能を分類する。
2. 対象会議と例外会議を定義し、録音通知とオプトアウト手順を決める。
3. KPIイベントと運用ダッシュボードを実装する。
4. 旧ツールの利用機能を、録音、文字起こし、要約、検索、共有、クリップ、連携、過去データに分解する。
5. 5〜10人のパイロットを選び、会議タイプが偏らないようにする。

### Phase 1：壊れ方を小さい母数で出す

1. カボスとtl;dvを並行稼働し、失敗した会議だけ原因分類する。
2. `queued`の滞留、確定文字起こし失敗、Drive出力成功0の原因を最優先で解消する。
3. 要約・決定事項・担当付き宿題・全文文字起こしを標準成果物として自動生成する。
4. 話者精度は10会議PoCで測り、60分会議90秒以内の修正を満たすか確認する。
5. 旧ツールへ戻った理由を「参加失敗」「品質不足」「探せない」「共有しにくい」「習慣」に分ける。

### Phase 2：1部署で標準業務にする

1. 対象カレンダー会議は招待だけでカボスが参加する状態にする。
2. 初回15分のオンボーディングと1ページの利用ガイドを作る。
3. 成果物の検索、共有、修正、削除を非開発者だけで完了できるようにする。
4. 問い合わせ窓口、障害時の手動再処理、旧ツールへの限定フォールバックを運用化する。
5. 部署責任者が週次KPIを確認し、未達理由を機能課題と運用課題に分ける。

### Phase 3：全社既定に耐える基盤へ変える

1. 1台のMacを単一障害点にしない。予備実行ノードまたはクラウド実行への切替手順を用意し、四半期ごとに復旧試験する。
2. Google Workspace等の会社IDと権限を揃え、会議参加者以外への不用意な公開を防ぐ。
3. 監視をダッシュボードHTTPだけでなく、参加、録音、確定文字起こし、成果物公開の各段階に置く。
4. 重要会議の優先処理、容量上限、同時会議数、外部API障害時の再試行を定義する。
5. 部署ごとの例外を吸収したうえで、対象会議はカボスを既定にする。

### Phase 4：旧ツールを安全に止める

1. tl;dvの新規録音を停止し、必要な管理者だけ30日間フォールバック可能にする。
2. 過去データは、移行対象、閲覧専用アーカイブ、削除対象に分ける。
3. 旧ツールでしかできない機能には、例外利用の期限と終了条件を付ける。
4. 4週連続で最終KPIを満たしたあと、ライセンスを縮小・解約する。

## 6. 優先順位

### P0：置き換え前に必須

- 対象会議と例外の定義
- KPIイベント計測
- 確定文字起こしの待機・失敗解消
- Driveまたは同等成果物の公開成功
- 自動要約・決定事項・宿題の標準成果物
- 録音同意、権限、保持、削除ポリシー
- バックアップと復元手順

### P1：部署展開前に必須

- 話者確認PoCと修正UX
- 検索・共有導線
- カレンダー自動参加の実績100会議
- 問い合わせ・再処理ランブック
- 利用状況と失敗理由の週次ダッシュボード

### P2：全社既定前に必須

- 実行基盤の冗長化
- 会社ID・権限の統合
- 容量計画とコスト実測
- 過去tl;dvデータの移行またはアーカイブ

## 7. 役割

| 役割 | 責任 |
|---|---|
| プロダクト責任者 | 対象会議、KPI、段階移行のGo/No-Go |
| 技術運用責任者 | 可用性、障害対応、バックアップ、容量 |
| 情報管理責任者 | 同意、閲覧権限、保持、削除、声紋等の機微情報 |
| パイロット責任者 | 利用者選定、週次レビュー、戻り理由の収集 |
| 利用者 | 品質評価、話者修正、フォールバック理由の記録 |

## 8. Go / Hold / Rollback

- **Go**: Exit KPIを必要期間満たし、重大事故0、次段階の運用責任者が決まっている。
- **Hold**: KPI未達だが、原因と2週間以内の改善策が特定できている。
- **Rollback**: 復元不能データ消失、権限事故、対象会議成功カバレッジ70%未満が2週連続、P1障害が週2件以上、または利用者が旧ツールへ戻る割合20%以上。

## 9. 次に決めること

1. Phase 1の5〜10人をどの部署から選ぶか。
2. 「対象社内会議」と「録音しない例外」をどこで線引きするか。
3. tl;dvで現在使っている機能と過去データを、何を残すか。
4. 会議後15分以内に必ず必要な成果物を、全文文字起こし、要約、決定事項、宿題のどこまでとするか。

この4点が決まれば、Phase 0を2週間で開始できる。

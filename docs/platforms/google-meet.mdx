This page covers the Google Meet specifics: how to extract IDs, what to expect during admission, and common failure modes.

## Native meeting ID

Use the meeting code from the URL:

- URL: `https://meet.google.com/abc-defg-hij`
- `native_meeting_id`: `abc-defg-hij`

Google Workspace accounts may use custom nickname URLs (e.g. `https://meet.google.com/my-team-standup`). These are also supported as `native_meeting_id`.

<Note>
Google Meet `/lookup/` URLs are internal redirect links and cannot be joined directly. Use the standard meeting link from your calendar invite instead.
</Note>

## Admission model

Most Google Meet meetings require the host to admit the bot from the waiting room.

Typical lifecycle:

1. Bot joins and waits in the lobby (`awaiting_admission`)
2. Host admits the bot
3. Bot becomes `active`

If the bot is never admitted, you will not get a meaningful transcript or recording.

## Authenticated auto-join from the calendar

Calendar-launched bots join as anonymous guests by default, so they sit in the lobby until a host admits them. Reusing the saved browser-session profile lets them join signed in instead.

Setup:

1. **Save the login once.** Open the browser session VNC page, sign in to Google as `KABOSU_CALENDAR_ACCOUNT_EMAIL`, then trigger a save (`save_storage`, or stop the session). Cookies — including in-memory session cookies — are written to `Default/cdp-cookies.json` and uploaded with the rest of the profile.
2. **Enable the flag.** Set `KABOSU_MEET_AUTHENTICATED=true` for calendar-service and restart it. Only Google Meet events get `authenticated: true`; other platforms are unchanged.
3. **Embed the VNC page from another host (optional).** If the dashboard runs on a different origin (e.g. Cloud Run), list it in `BROWSER_FRAME_ANCESTORS` on meeting-api, comma separated: `BROWSER_FRAME_ANCESTORS=https://dashboard.example.run.app`. Each entry must be a bare `scheme://host[:port]`; entries with a path, credentials, query or fragment are ignored with a warning.

Rollback: set `KABOSU_MEET_AUTHENTICATED=false` (or unset it) and restart calendar-service — bots go back to anonymous joins. Clearing `BROWSER_FRAME_ANCESTORS` restores the localhost/same-host-only `frame-ancestors` policy. Neither change touches the saved profile.

<Note>
If no profile has been saved yet, leave `KABOSU_MEET_AUTHENTICATED=false`. Enabling it without a stored login makes joins fail rather than fall back to a guest join.
</Note>

## API example

```bash
curl -X POST "$API_BASE/bots" \
  -H "Content-Type: application/json" \
  -H "X-API-Key: $API_KEY" \
  -d '{
    "platform": "google_meet",
    "native_meeting_id": "abc-defg-hij",
    "recording_enabled": true,
    "transcribe_enabled": true,
    "transcription_tier": "realtime"
  }'
```

## Common issues

### Bot joins then leaves quickly

Most often:

- the bot was not admitted
- the meeting is over / invalid link
- policy restrictions on the meeting (host settings)

Check the meeting status history and bot logs, and confirm the host admits the bot.

### No transcript segments

Common causes:

- `transcribe_enabled=false`
- the meeting was silent (or audio capture failed)

See:

- [Troubleshooting](../troubleshooting)
